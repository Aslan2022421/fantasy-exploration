# 建構計畫

資料重建後的建構順序。每個階段是一個小切片：短分支、做完能玩，使用者試玩同意後合回 main。

**目前執行：階段 0～4，先用最簡單的做法跑起來，試了再調。**

## 世界的形狀（階段 2 起）

- 兩層：世界層一格＝一個局部區域（`ZONE_SIZE` 96）。世界層一開始整個算好，存每區的平均氣候、氣候標籤、生態標籤與 `numbers`（每區幾個數字，各階段用到時再加）。局部區域用到才生、生過就留在記憶體；世界大到記憶體或速度吃緊時再加淘汰。
- 世界層大小是 `ZONES_X`、`ZONES_Y`，階段 2 先做 3×3。量過 96×96 的世界：全展開約 76 秒、243 MB，所以不能一次展開，一定要兩層。
- 局部區域只能由「種子＋座標（＋世界層那格的資料）」生成，不看生成順序與玩家位置。每格的小變化用雜湊，不用亂數分流（分流照順序取值）。地圖不進存檔，讀檔時重生再套回紀錄。
- 全世界共用一套格子座標，跨區無縫，世界外不能走。
- 每格分地形層與物件層（使用者定）：地形層是地面本身（`data/terrain`：水、草地、沙地、雪地、泥地、山地）；會變成資源的都是物件層（`data/object`：樹、矮叢，之後的礦脈）。生態的 `flora` 引用物件，撒在該生態的平地與山地上（使用者定：山地也有樹；山地越高樹越少，高出山地門檻 0.2 就沒有樹；山上的樹顏色往山地的色調靠五成）。樹冠底下要是平地（使用者定：樹幹被破壞後樹冠會消失），所以樹冠只長在跟樹幹同一個高度層、而且長得出植物的格子上；樹幹永遠露出來，不被別棵的樹冠蓋住。物件依物種有大小（`sizes`，直徑幾格，使用者定）：矮叢 1、闊葉樹與針葉樹 2～3 偶爾 4（老樹）、叢林 2～4。每棵有一個錨點（左上角，只看種子＋座標），往右下長出接近圓形的一團，重疊時取雜湊最小的那棵；撒錨點的機率除以平均佔地，林子密度不會因樹變大而暴增。樹冠右上亮、左下暗（`src/world/footprint.js`）。樹有樹幹（資料的 `trunk`，使用者定）：樹冠正中間那一格是樹幹，畫成 `Φ`、走不過去，樹冠其他格走得過去；矮叢沒有樹幹。畫的時候物件字元疊在地形上，背景用地面的，樹底下也看得到地面的光照。地形與物件都走得過去，那格才走得過去。
- 立體感（偽 3D）分三層，都只影響畫面，不影響走路與地形：
  - 大地形與分層（`src/world/landform.js`）：高度＝大地形（波長 320 格）＋細節（波長 48 格、振幅 0.12）。高度層只看大地形：水面固定第 0 層，陸地第 1～4 層（大地形每 0.22 一層），一區裡陸地通常兩三層，出現看得出的盆地與台地。細節只影響亮度、字元與山地，不切台階。`?flat` 對照模式的亮度看絕對高度層（越高越亮），坡向明暗（Horn 法，光從右上，方位角 45°、高度角 45°）只微調 -2～+1 級；預設畫面看相對高度，見下面「Z 高度」。山地（高度含細節＞0.42）在所屬大地形層之上，用完整高度每 0.05 再加一層、最多 3 層（最高第 7 層）；`?flat` 時山地的坡向明暗加強到 -4～+2 級。
  - 水：全世界同一條水線（-0.34，不隨濕度移動），水面一定是最低的第 0 層，湖岸有一圈岸壁。水面下 0.07 以上算深水；淺水只留在深水 3 格內，零星的淺水窪改回陸地。水依深度變暗（越深越暗）。
  - 彩度只留 55%（`SATURATION`）：地形種類仍靠色相分辨，畫面上最強的差異是亮暗。
  - 背景也帶光：背景是地形色的三成多亮，跟字元一起依明暗調整，整格看得出亮暗。
  - 台地與立面：立面只畫在高度層的邊界。北邊高一層的格子是立面，高兩層以上再多一行；比南邊高的格子是台地邊緣（稍亮）。
  - 高低的畫法（使用者看過七種並排後，挑定「往左下拉側面與影子、影子只調暗」那一版）：亮度用生成時算好的級數（陸地看絕對高度層＋坡向明暗，光從右上照；水看深度）。比較高的地形往左下拉出 2～3 格的側面（高一層 2 格、兩層以上 3 格），用高處地形自己的字元、顏色調暗（離高處 1、2、3 格分別 0.6、0.5、0.42）。有高度的物件往左下投影子（樹 3 格、矮叢 2 格），影子只讓地面調暗到 0.6、不換字元；有物件的格子是被照亮的樹冠，不吃影子。地面背景是地形色的 32%，字元每格有兩成機率往暗、兩成往亮偏一階。程式在 `src/view/worldview.js`、`src/view/extrude.js`；網址加 `?flat` 不畫側面與影子。試過但使用者覺得不對的：每層往上抬的斜投影、側面加斜線影子、以冒險者為準的相對亮度（三階加牆、四階加輪廓）、絕對亮度加粗崖邊 `#` 與暗帶、地面低對比。這幾種都留在開發用的比較頁 `/compare.html`（`src/dev/`），不進遊戲。
  - 字形（使用者定，`src/view/glyphs.js`）：字形代表「地表長什麼樣」，顏色代表「是什麼材質」，亮度輔助高低與深淺；每種地形只用兩三個代表字元。起伏：空白 → `.` → `·` → `∙`，由平地到有起伏，所有陸地共用，依坡度選（陸地約一半最平是空白）。植被（草地）：`,` 碎葉、細草；`'` 稀疏草叢；`"` 較高的草叢；`:` 苔蘚；`;` 混合植被。波紋：空白、`-`、`~`、`≈`，深藍色是水、沙黃色是沙地。高起：沙黃色的 `^` 是沙丘；山地坡陡用實心三角 `▲`（山坡），其餘用線三角 `^`（山地）。以下是 Claude 補的提議、使用者沒反對：深水大多空白配深藍、偶爾 `≈`，淺水 `-`、`~`；沙地平坦處空白、`-`、`~`，坡陡出現 `^`；草地乾燥處多 `,` `'`、濕潤處多 `"`、寒冷潮濕處出現 `:`、生態交界出現 `;`、很陡的草坡用起伏字元；泥地是起伏字元加零星 `,`，寒冷時有 `:`；雪地只有起伏字元。資料裡每種地形寫 `style`（套哪一套規則）與 `glyphs`（會用到的字元）。（試過「依亮度從字元階梯選字」，同一個字代表好幾種地形、字形跟著明暗變，使用者看不懂，已取代。）
  - 字元與顏色先算成表（地形數×8 級×4 種立面），用到才染色，快取有上限。
- 沒有岩壁：試過一種走不過去的「岩壁」地形，它不是用來呈現立體，畫出來又不好看，使用者決定拿掉。之後要障礙物，照卡德洞窟的做法放進物件層（可以挖、可以產出資源），要先討論。
- ROT.js 的注意事項：`Noise.Simplex` 預設 256 個梯度，每 256 個晶格單位重複一次，所以用 4096；`Noise.Simplex` 的建構、`Map.Cellular`、`StringGenerator` 會用全域亂數，用之前存下全域狀態、設成「種子＋用途」，用完還原。`Map.Cellular` 一區一區各自跑會在區界接不起來，地形不用它。
- 地形比例用 `node tools/measure-terrain.mjs` 量；參數在 `src/world/terrain.js` 的 `GEN`。

## 每個階段都照做的

1. 開工前把規格與數字列給使用者確認。
2. 太大就拆成兩三個小交辦，各自跑 `check`、提交。
3. 最後由使用者試玩，同意才合回 main，開發日誌補一段。
4. 流程改進用到時才建：階段 0 有 `check`、`play`、資料驅動測試、一效果一元件；階段 1 起有重放；有介面文字時加字的檢查；要截圖時加 `shot` 與情境；調平衡時加 `sim`。
5. 階段 0 做完量 `check` 的時間並回報。
